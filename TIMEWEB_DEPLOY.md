# Развёртывание в Timeweb Cloud App Platform

## Что выбирать в панели

- Тип: **Docker → Dockerfile**
- Репозиторий: ваш GitHub-репозиторий
- Ветка: **main**
- Путь до директории проекта: **оставить пустым**
- Путь проверки состояния: можно оставить пустым — `HEALTHCHECK` уже задан в Dockerfile. Если Dockerfile healthcheck будет удалён, используйте `/healthz`.
- Приватная сеть: не нужна, если приложение не подключается к другим приватным сервисам.
- Рекомендуемый стартовый сервер: 2 vCPU / 4 ГБ RAM. Для тяжёлой генерации расписания можно использовать 4 vCPU / 8 ГБ RAM.

## Порт

Приложение слушает `0.0.0.0:5000`, а Dockerfile содержит `EXPOSE 5000`. Timeweb App Platform автоматически проксирует внешний HTTP/HTTPS-трафик на этот порт.

## Переменные

Базовые значения уже заданы в Dockerfile. В панели их дублировать не обязательно.

Ключевые значения:

- `PORT=5000`
- `DATA_DIR=/data`
- `NODE_WORKER_MAX_OLD_SPACE_MB=192`

Секреты, токены и пароли, если они появятся, задавайте только через переменные окружения Timeweb и не добавляйте в Git.

## ВАЖНО: данные `/data`

App Platform при новом деплое создаёт новый контейнер. Локальные файлы контейнера не являются постоянным хранилищем между деплоями.

Текущее приложение хранит рабочее состояние в:

- `/data/storage.json`
- `/data/backups/`
- `/data/public-*.json*`
- `/data/public-shards/`

Поэтому **не считайте `/data` постоянным хранилищем**. Для рабочего сервиса данные нужно вынести во внешнее постоянное хранилище (например, БД / S3) либо организовать отдельный механизм сохранения и восстановления перед каждым редеплоем.

## Проверка после деплоя

1. На вкладке «Деплой» сборка должна завершиться без ошибок.
2. На вкладке «Логи приложения» Gunicorn должен стартовать на `0.0.0.0:5000`.
3. `https://<технический-домен>/healthz` должен вернуть JSON вида `{"ok":true}`.
4. После этого открыть корень технического домена и проверить интерфейс.
