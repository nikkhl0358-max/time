# Неделя 9: исправление сопоставления после восстановления 7-й недели

Исправлен `frontend/src/bulkWeekSnapshot.mjs`: при копировании недели, если исходный `loadId` не найден в графике целевой, допускается только строгое уникальное сопоставление по набору участников (включая подгруппы), предмету, преподавателю, типу, формату, половинке и слою. Копия использует канонический `loadId` целевой недели. Неоднозначные соответствия остаются без автоматической перепривязки. Учитываются лимиты по количеству требуемых пар.

`frontend/src/test-week9-reconcile.mjs` — два теста: восстановленный `loadId` при однозначном совпадении; отказ от неоднозначного совпадения.

`tools/week9_relink_preview.py` — **только чтение** существующей выгрузки: сформировать отчёт о возможной перепривязке, без изменений базы:

```
python3 tools/week9_relink_preview.py timeweb_week9_diagnostics_20261019.json.gz --output week9_relink_preview.json
```

Для прикреплённого снимка найдено 688 строгих совпадений по критериям идентичности, но лишь 450 пар дают однозначное соответствие один-к-одному. Это потенциальные совпадения, а не подтверждённые безопасные переносы. 116 целевых записей имеют более одного подходящего исходного занятия. До применения необходима проверка конфликтов аудитории, преподавателя, группы, занятых слотов и пересчёт графика на конкретном снимке.

**Внимание:** исправление алгоритма копирования не исправляет существующие данные недели 9 автоматически. Не запускайте повторное копирование на рабочей базе и не загружайте диагностический JSON в PostgreSQL. Рабочая БД не изменялась. Полная сборка приложения и развёртывание здесь не подтверждены.
