# Проверка безопасности и качества — 2026-11-06

## Согласованный объём
- Локальный проект; пользователь разрешил проверку API и перенос входа на сервер.
- Публичный просмотр сохраняется, рабочие данные закрываются серверной сессией.
- Исправления сохраняются в dev; production не развёртывается в рамках задачи.

## Слепые зоны
- Авторизация была клиентской; X-Admin-User-Id не доказывал личность.
- В tools/ находится отдельное устаревшее приложение, которое нельзя считать защищённым текущими исправлениями корня.
- Планировщики содержат разные ядра: полное автоматическое выравнивание требует проверки бизнес-правил.
- Существующие пароли SHA256 требуют совместимости; новые серверные пароли должны храниться стойким хешем.

## Решения
- Закрывать private API по умолчанию, публичные маршруты перечислить явно.
- Для первого пользователя нужен серверный AUTH_SETUP_TOKEN, чтобы посторонний не захватил пустую установку.
- Ограничить повтор запросов временными ошибками и сетевыми сбоями.

## Проверки и оставшиеся ограничения
- Vite и React plugin обновлены; сборка прошла также на Node 22. Lockfile фиксирует зависимости, Docker использует npm ci.
- npm audit: 0 известных уязвимостей после обновления и удаления неиспользуемого xlsx.
- xlsx-js-style содержит старую копию SheetJS; аудит npm не доказывает безопасность импорта Excel. Замена требует регрессии импорта/стилей экспорта.
- Smoke звонков, запрета слотов, группового генератора, customWeeks и повторов запросов проходят.
- check_scheduler_parity.py падает на прежних расхождениях ядер; check_group_batch_scheduler_smoke.py ожидает устаревшие defaults 12/6000 вместо текущих 4/3000. Тесты не ослаблялись.
- tools/app.py перенаправляет на защищённый корневой API; самостоятельная архивная сборка tools/ не поддерживается.
- Live API: HEAD без входа вернул HTTP 200 и Content-Length 57507939. Тело не скачивалось, операции записи не выполнялись.

## Итог защиты
- 13 проверок авторизации и интеграции с SQLite проходят: вход, миграция пароля, logout, отзыв cookie, CSRF, rate limit, role escalation, запоздавший autosave и bounded gzip.
- Secure cookie включена по умолчанию; локально без HTTPS запускайте AUTH_COOKIE_SECURE=0.
- За reverse proxy успешный вход сбрасывает счётчик, чтобы общий адрес прокси не блокировал коллектив.
- Для совместимости панели управления пользователями закрытый рабочий JSON пока содержит passwordHash. Сотрудники с доступом к редактору могут читать эти хеши; полный перенос управления пользователями в отдельный API и удаление хешей из transport остаётся отдельной задачей.
- Полная декомпозиция существующих монолитов не выполнялась: новые helpers короткие, старые функции требуют последовательного рефакторинга с проверкой бизнес-сценариев.
- Codex-setup не найден поиском плагинов и локальных скиллов. Использованы доступные fable-guide, find-skills, uml-project-diagrammer, security/code-review subagents и локальный pre-commit hook.

## Оптимизация 50+ МБ полезной нагрузки (2026-11-06)
- Проблема: `/api/storage/schedule-data-v2` отдавал 57,5 МБ сырого JSON при каждом входе в редактор (основной объём: `publishedSnapshot` ~28,65 МБ и `schedule` ~24,40 МБ).
- Решение:
  1. Реализован модульный transport (`editor_transport.py`, `editor_state.py`, `frontend/src/editorTransport.js`).
  2. Первичный вход запрашивает легковесный `bootstrap` (~675 КБ JSON, ~71 КБ gzip) — сокращение стартового трафика более чем на 98%.
  3. Тяжёлые разделы (`loads`, `schedule`, `graphState`, `publishedSnapshot`, `_groupRestoreUndo`) подгружаются отложено при переходе на соответствующие вкладки.
  4. Защита от потери данных: частичная перезапись неполного проекта блокируется (`complete_project` / `partial_write_error` возвращают 409).
  5. Проверка транзакционной согласованности: токены ревизий (`revision_token`) предотвращают смешивание разделов из разных версий проекта.
  6. Потоковый экспорт: `GET /api/editor/<key>/export` позволяет выгрузить полный JSON без дополнительного расхода оперативной памяти сервера на буферизацию.
  7. ETag-кеширование: повторные обращения к неизменённым разделам возвращают HTTP 304 Not Modified.
  8. Полный сквозной прогон в Playwright (`tools/run-e2e-browser-test.cjs`) подтвердил корректную авторизацию, отсутствие падений React и загрузку исключительно запрошенных секций.
