# Расписание КТМУ — готовая версия для Amvera

Проект состоит из React/Vite интерфейса и Flask API. На Amvera используется **Docker-сборка**: фронтенд автоматически собирается из `frontend/src`, после чего готовый `dist` копируется в `static` внутри итогового контейнера. Поэтому отдельно запускать `build.sh` перед загрузкой на Amvera не нужно.

## Структура

```text
raspisanie/
├── Dockerfile
├── amvera.yaml
├── requirements.txt
├── app.py
├── build.sh                 # только для локальной проверки без Docker
└── frontend/
    ├── package.json
    └── src/
        ├── App.jsx
        ├── main.jsx
        └── storage.js
```

## Развёртывание на Amvera

1. Загрузите содержимое папки `raspisanie` в проект Amvera / отправьте в репозиторий проекта.
2. `amvera.yaml` уже настроен на Docker и `Dockerfile` в корне.
3. Подключите постоянное хранилище с точкой монтирования `/data`.
4. Запустите сборку.

Dockerfile сам:
- устанавливает npm-зависимости;
- выполняет `npm run build`;
- устанавливает Python-зависимости;
- кладёт свежую Vite-сборку в `/app/static`;
- запускает Flask через Gunicorn.

Данные приложения сохраняются в `/data/storage.json`. Gunicorn запускается одним worker-процессом с несколькими потоками, чтобы файловое хранилище не записывалось одновременно разными процессами.

## Локальный запуск через Docker

```bash
docker build -t ktmu-schedule .
docker run --rm -p 5000:5000 -v "$(pwd)/local-data:/data" ktmu-schedule
```

После этого откройте `http://localhost:5000`.

## Локальный запуск без Docker

Сначала соберите интерфейс:

```bash
./build.sh
```

Затем установите Python-зависимости и запустите приложение:

```bash
pip install -r requirements.txt
python app.py
```

## Что изменено в логике

- учебный план разделён по специальности, базе поступления (после 9 / после 11) и сквозному семестру;
- у группы хранится база поступления и срок программы в семестрах;
- старые схемы недель (`все`, `числитель`, `знаменатель`, выбор недель) автоматически мигрируют в единый понедельный график;
- новые нагрузки не назначают недели: конкретные недели задаются только в разделе «Графики»;
- графики доступны по группе и по потоку и показывают превышение часов учебного плана;
- нагрузку можно массово создать для всех групп выбранной специальности;
- расписание можно листать по неделям или смотреть целиком; отображаются номера недель и различаются числитель/знаменатель;
- в заменах можно менять номер пары в течение дня;
- семестровый публичный просмотр использует табличную структуру «день / время / даты / название / место / преподаватель или группа»;
- преподавателя можно искать по фамилии и по ЦК;
- пересдачи и аттестации не сохраняются при конфликте группы, преподавателя или аудитории; учитываются актуальные замены/перестановки;
- виды аттестаций дополняются вручную;
- у практики отдельно задаются тип и собственное название.


## Новый семестр
В административной боковой панели есть глобальная кнопка «Новый семестр». Она архивирует текущий семестр в разделе «Версии», сохраняет справочники/учебные планы/пользователей и очищает только семестровые назначения. Перевод групп на следующий учебный семестр выполняется только при включении отдельной опции. Пересборка приложения эту операцию не запускает.

### Дистанционные практики и подгруппы
В режиме `Авто` практические занятия одного преподавателя могут объединять обе подгруппы совместимого потока в одну ДО-пару. Совместимость требует одинаковых направления/специальности, курса, дисциплины, преподавателя, вида занятия и недельного графика. «Вся группа» остаётся отдельным контуром.

### Обязательные ДО-сборки практики
Для `Пр` с разрешённым ДО и форматом `Авто` можно задать `Общих ДО-сборок`. Это точное обязательное число общих дистанционных пар за семестр. Остальные пары остаются очными. Если все обязательные сборки разместить нельзя, генератор показывает их как неразмещённые.

### Работа с подгруппами (v49)
Для практических нагрузок состав подгрупп теперь задаётся вручную отдельно для ДО и очного режима. Обязательные общие ДО-сборки используют только явно выбранную ДО-связку; очная связка задаётся независимо.

### Порядок лекций и практик
Если по одной дисциплине у группы/подгруппы в пересекающиеся недели есть лекционные и практические занятия, автогенератор предпочитает порядок «лекция → практика», по возможности подряд в один день. Ручные закрепления остаются приоритетными.


## v52 — исправлен расчёт календарных недель
- Исправлена работа с датами в браузерах с положительным часовым поясом (например, UTC+3): календарная дата больше не сдвигается на предыдущий день через `toISOString()`.
- Навигация публичного расписания теперь строит учебную неделю строго от понедельника; диапазон отображается по активным учебным дням этой недели.
- Номер недели и числитель/знаменатель считаются от понедельника первой недели семестра без часового сдвига.
- Исправление применяется ко всем внутренним операциям `addDays`/`mondayOf`, поэтому даты в недельных представлениях становятся согласованными.
- Хранилище `/data` и существующие данные не изменяются и не инициализируются заново.

### Календарные границы
Расписание использует календарные недели с понедельника, однако обычные занятия показываются только внутри `semesterStart`–`semesterEnd`. Праздничные даты и исключения календаря с запретом обычных занятий не создают фактическое занятие на эту дату.

### Компактность расписания (v54)
Автоматическая расстановка ориентируется на 4–5 пар у группы в день непрерывным блоком. Новые окна у групп и преподавателей запрещены для автоматически размещаемых занятий. Ручные закрепления не снимаются; если они уже образуют окно, генератор старается его заполнить и не увеличивать разрыв.


### v55 — начало учебного дня
Автогенератор не обязан начинать день группы с первой пары. При равных вариантах он предпочитает компактный непрерывный блок со 2-й/3-й пары; первая пара остаётся допустимой, когда она действительно нужна.


## v56
- Целевой диапазон учебного дня группы: 3–6 пар подряд.
- 3, 4, 5 и 6 пар считаются нормальными вариантами без штрафа.
- 1–2 пары остаются нежелательными. Окна по-прежнему не создаются автоматически.

### v57
Автогенератор предпочитает 3–5 пар в день без окон; 6-я пара используется только при необходимости. Для одной дисциплины лекция автоматически размещается раньше практики, в том числе относительно закреплённой практики.

### Правила компактности v57
Автогенератор предпочитает 4–5 непрерывных пар у группы, допускает 3 пары без существенного штрафа и считает 6 пар нежелательным запасным вариантом. Для одной дисциплины автоматическая расстановка соблюдает порядок: лекция раньше практики; ручные закрепления имеют приоритет.

### v58: жёсткий запрет окон
При автоматической генерации окна у групп не допускаются. Генератор не ставит и не переносит занятие, если действие разрывает непрерывный блок пар; невозможная без окна пара остаётся неразмещённой. Ручные закрепления не снимаются автоматически.

### Ограничения дневной нагрузки (v59)
В административном меню есть отдельная вкладка «Ограничения». В ней можно настроить для каждого курса и базы поступления (после 9 / после 11 класса) минимальную целевую и максимальную дневную нагрузку, а также последнюю допустимую пару. Автогенератор не использует недоступные пары преподавателя, не создаёт окна и никогда не ставит группе все шесть пар. При включённом правиле день с физической культурой может получить +1 к максимуму, но не более пяти пар.

### v60
Во вкладке «Ограничения» дневная нагрузка задаётся только через минимум и максимум пар для курса и базы 9/11 классов. Отдельный лимит «не позже пары» убран. Недоступные пары преподавателя являются абсолютным запретом для автоматической расстановки; при отсутствии допустимого времени занятие остаётся неразмещённым.

### v61: стабильность расписания между неделями
Генератор старается сохранять одинаковый недельный шаблон: занятия одной группы по возможности остаются в тех же днях и на тех же номерах пар в соседних учебных неделях. Перенос допускается только когда стабильный слот нарушает жёсткие ограничения (доступность преподавателя, праздник, практика, конфликт, аудитория и т. п.).

### Двухнедельный шаблон расписания
Автогенератор поддерживает стабильность по циклу числитель/знаменатель: нечётные недели стараются повторять нечётные, а чётные — чётные. Различия между двумя шаблонами допустимы; жёсткие ограничения имеют приоритет.


### v63 — приоритет ранее поставленных пар и временная блокировка дня группы
- При пересчёте ранее автоматически размещённые обычные пары используются как каркас, если их старый слот всё ещё удовлетворяет жёстким ограничениям. Новая нагрузка поздних недель заполняет свободные слоты, а не перестраивает ранние недели.
- Двухнедельная стабильность стала направленной: поздняя неделя подстраивается под предыдущую неделю той же чётности (1→3→5, 2→4→6).
- В недельном расписании группы в заголовке каждого дня есть временная блокировка дня. Заблокированная дата является hard constraint авторасстановки для этой группы.
- Временные блокировки очищаются при создании нового семестра и не затрагивают постоянные справочники.


## v64 — ручное добавление в закрытый день
- Временная блокировка дня группы действует только на автоматическую расстановку.
- В режиме ручного редактирования в закрытый день можно добавлять занятия в свободные ячейки.
- Визуальная отметка закрытого дня сохраняется; подсказка явно указывает, что ручное редактирование разрешено.

Исправлена ошибка production-сборки Vite, вызванная CSS блока временной блокировки дня группы, попавшим за пределы template string в `App.jsx`.

### Двухнедельный шаблон (v66)
Компактность и отсутствие окон считаются отдельно для каждой недели. Чётный и нечётный шаблоны независимы, но чередующиеся лекция/практика одной дисциплины по возможности занимают один и тот же слот через неделю.

### Заморозка дня (v67)
В недельном виде группы день можно «заморозить». Текущие занятия этого дня сохраняют свои слоты при последующих генерациях, а новые занятия автоматически в этот день не добавляются. Ручное редактирование разрешено. «Закрыть день» и «Заморозить день» — разные функции: закрытие запрещает автодобавление независимо от текущего состава, заморозка дополнительно фиксирует уже расставленные пары.

### v68
Закрытый день группы является жёстким запретом для автоматической расстановки (ручные закрепления разрешены). Во вкладке «Графики» показываются суммарные пары и академические часы по каждой учебной неделе.

### v69: первая и последняя пара дня
В настройке нагрузки значения «первая в дне» и «последняя в дне» относятся к границам фактического непрерывного блока занятий группы. Например, при расписании 3–5 первой считается 3-я пара, а последней — 5-я; привязки к фиксированным номерам 1 и 6 нет.

### v70
Автогенератор оценивает окна и компактность отдельно по каждой неделе. Чётная и нечётная сетки не смешиваются. Для чередующихся через неделю лекции/практики сильно приоритетен один и тот же слот двухнедельного шаблона.

## v75 — недельная нагрузка подгрупп

В расчёте недельного лимита группы занятие одной из двух подгрупп имеет вес 0,5 пары группы; занятие всей группы — 1. Для конфликтов преподавателя, аудитории и самой подгруппы занятие по-прежнему занимает полный временной слот.

## v77 — приоритет дефицитных занятий

При автогенерации первыми обрабатываются нагрузки преподавателей с наиболее узкой доступностью. Далее учитываются число реально допустимых временных слотов и доступность подходящих аудиторий. Это позволяет не занимать редкие свободные окна «гибкими» дисциплинами до того, как будут размещены занятия преподавателей с жёсткими ограничениями.

### v78: единый hardest-first
Автографик и генератор расписания используют единый принцип: сначала ограниченные по доступности преподавателя/слотам/аудиториям нагрузки, затем более гибкие. В графиках виден индикатор доступности и итоговый порядок приоритета.


### Логика автографика (v85)
Автографик сначала формирует последовательность обучения, затем оптимизирует её по доступности преподавателей. Лекция открывает дисциплину; практические и лабораторные занятия не начинаются раньше первой лекции; обычные часы по возможности распределяются последовательно и без избыточного сгущения; контрольные работы и зачёты идут после основной части своей дисциплины.


### v91
Автогенерация сильнее учитывает полностью недоступные дни преподавателей: меньшему числу доступных дней даётся приоритет до сравнения отдельных свободных слотов.


### v94: учёт графика преподавателя в автографике
При автоматическом распределении часов группы по неделям учитывается не только шаблон доступности преподавателя, но и уже назначенные ему часы по другим группам. Чем плотнее его график в конкретной неделе, тем ниже приоритет этой недели; при отсутствии свободной ёмкости неделя исключается.

## v102 — процент ДО для практик
Для практической нагрузки (`Пр`) в режиме `Авто` можно задать процент дистанционных занятий. Система автоматически переводит процент в число общих ДО-сборок по реально совпадающим слоям понедельного графика выбранных в ДО-связке подгрупп. При изменении графика количество сборок пересчитывается автоматически.

Очная связка подгрупп теперь допускает разные дисциплины, виды занятий и преподавателей: для одновременной очной работы можно связать любую другую подгрупповую нагрузку той же группы.

### v105
Уточнён интерфейс нагрузок: активный формат явно выделяется, выбранные аудитории показаны номерами/названиями. Во всех административных разделах доступна явная кнопка ручного сохранения текущего состояния.

### v107
Закрытые дни групп теперь строго исключаются из автоматической и предлагаемой ручной расстановки. Автопереносы в недельном просмотре показывают только реально существующие в этой неделе пары и только полезные перестановки.

### v108: перенос повторяющихся слотов
В ручном расписании перенос уже размещённого занятия применяется ко всему повторяющемуся слоту на всех неделях действия конкретного шаблона. Интерфейс показывает диапазон недель до подтверждения переноса.

### v109
Добавлены автоматическая синхронизация изменений пользователей, информационная плашка о чужих изменениях, поддержка 1 ак.ч. как половины пары и корректный учёт подгрупп в выполнении плана.

### v111: производительность генератора
Пересчёт оптимизирован для больших семестров: дорогие MRV/compact/swap/ejection проверки выполняются на ограниченном наборе наиболее перспективных кандидатов и имеют раннюю остановку.

### Серверная генерация
Начиная с v112 кнопка генерации отправляет снимок данных на `/api/schedule/generate`. Flask запускает `server_scheduler.mjs` отдельным Node-процессом и возвращает идентификатор задачи. Клиент опрашивает статус и применяет результат только после завершения. Для защиты от одновременной тяжёлой нагрузки сервер исполняет одну задачу генерации за раз. Текущий JS-генератор во frontend сохранён как аварийный fallback.


## v116 — защита синхронизации генераторов
Перед локальной и Docker-сборкой автоматически сравнивается общее ядро планировщика в `frontend/src/App.jsx` и `server_scheduler.mjs`. Если версии расходятся, сборка завершается ошибкой. Это гарантирует одинаковую логику ДО-потоков, процентов лекций, половин пар и остальных ограничений на клиенте и сервере.

### Серверная генерация больших проектов
Начиная с v118 запуск генерации использует сохранённый `schedule-data-v2` на сервере. В POST-запрос не отправляется полный проект, поэтому размер учебного плана/расписания не раздувает команду запуска и не вызывает HTTP 413 из-за дублирования JSON.

## v1871 — аварийное восстановление пустого публичного контура
Если опубликованный снимок содержит 0 размещённых занятий, но рабочее расписание не пустое, публичный контур автоматически и только для чтения использует последнюю непустую неизменяемую публикацию из серверного архива. Группы, преподаватели и кабинеты пересобираются лениво; рабочая база и `publishedSnapshot` не изменяются.

## v1872 — фактические пары при проверке графика
Предупреждение «Сверх графика» считает только реально размещённые видимые фактические занятия. Неразмещённые остаточные строки и технические копии одной пары в том же слоте больше не создают ложное превышение графика. Разные реальные слоты по-прежнему учитываются отдельно.
