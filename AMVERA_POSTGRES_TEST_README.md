# Amvera: тестовая PostgreSQL-сборка

Основа: исходная версия Amvera (`timetable-code (1).tar`). Изменения: добавлен `pg_compat.py` из предоставленной Timeweb-версии; при наличии `DATABASE_URL` хранилище работает с PostgreSQL. Без `DATABASE_URL` используется прежний SQLite.

## Важное

- Разворачивать **только как отдельный тестовый проект** на Amvera, не обновлять рабочий сайт.
- PostgreSQL: база `timetabl`, пользователь `timetableuser`, внутренний хост `cnpg-timetable-rw`, порт 5432. Для тестового приложения задать `DATABASE_URL` через секреты окружения проекта; **не включать пароль в ZIP или git**. Пример: `postgresql://timetableuser:<PASSWORD>@cnpg-timetable-rw:5432/timetabl?sslmode=prefer` (внутренний TLS проверить по параметрам Amvera).
- Архив содержит полный код, а не резервную копию БД; данные уже загружены в PostgreSQL отдельно.
- Не запускать автоматическую публикацию, пересчёт или редактирование без предварительного снимка тестовой базы.
- Все 22 840 экземпляров и корректность графиков пока подтверждены только как подготовленные данные, а не поведением приложения.
- После запуска проверить /healthz, доступность интерфейса, группу и неделю 7, другие недели, справочники и сохранность нагрузки; прежде чем что-либо редактировать, снять pg_dump.

## Ограничения

Перенесён слой хранения, но полного интеграционного теста на живом кластере здесь нет. Amvera-версия приложения старше Timeweb-версии и может отличаться по поведению. Отдельные таблицы исторических публикаций в импортированной базе пусты (импортирована основная запись JSON), поэтому старые внешние публикационные архивы не восстановлены.
