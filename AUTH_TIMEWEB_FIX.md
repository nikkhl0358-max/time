# Исправление входа пользователей на Timeweb (06.11.2026)

## Изменения
- `app.py`: `/api/auth/session`, `/api/auth/login` и guard защищённых API читают только поле `users` из рабочей строки БД. **Весь проект не загружается** при обычной проверке сессии.
- PostgreSQL: авторизация открывает прямое соединение на чтение вместо общего `PgConnection`, который проверял таблицы и выполнял DDL на каждом подключении. Данные и таблицы не меняются.
- Временная недоступность PostgreSQL/SQLite даёт JSON с HTTP 503, а не ложный признак отсутствующих пользователей (и не HTML 500 при обычных ошибках подключения).
- Поддерживается формат пользователей внутри JSON-объекта и старый двойной JSON; хеши паролей и роли не изменяются.
- `tools/check_auth_projection.py`: 5 новых изолированных проверок чтения users, старого формата, недоступной базы и отсутствия лишнего DDL.

## Чего исправление НЕ делает
- Не регистрирует новых пользователей, не сбрасывает пароли, не меняет `DATABASE_URL`, `/data` и схему БД.
- Если прежняя PostgreSQL недоступна по сети или хостинг завершает процесс из-за RAM, вход по-прежнему не сможет завершиться. Проверить доступ к действующей БД и фактический лимит памяти контейнера.

## Timeweb: безопасное обновление
1. Создать резервную копию PostgreSQL и сохранить текущие настройки приложения (в особенности DATABASE_URL, AUTH_SECRET_KEY, /data).
2. Заменить код, не удаляя том/базу; перезапустить сборку.
3. Открыть `/api/auth/session`: `setupRequired:false` означает, что users найдены; 503 означает недоступность БД. **Не делать setup при 503.**
4. Авторизоваться под существующими реквизитами. Если 502 остаётся — посмотреть логи приложения и метрики памяти при самом запросе.
