# Timeweb Cloud: подключение существующей PostgreSQL

1. Загрузить этот проект в GitHub вместо старой версии (не загружать секреты).
2. Timeweb Cloud -> App Platform -> настройки деплоя: Dockerfile, каталог проекта пустой (корень), ветка main, путь проверки состояния `/healthz`.
3. Оставить `DATABASE_URL` с реальными параметрами доступа к существующей PostgreSQL. Не публиковать строку подключения в GitHub, переписках и скриншотах.
4. Если `DATABASE_URL` содержит `sslmode=verify-full`, на хосте приложения должен быть установлен корневой сертификат CA Timeweb и корректно указан `sslrootcert` (или системное доверенное хранилище); без этого SSL-подключение может не пройти.
5. Выполнить деплой, затем открыть `/api/storage-diagnostics` и убедиться, что `storage=postgresql`, `storageReady=true`, `sqliteOk=true` (поле сохранило старое название), ошибок нет.
6. Сверить содержимое групп, недель и опубликованного расписания с сохранённой копией. Перед любыми правками сделать SQL-дамп PostgreSQL в панели Timeweb.

Ограничения: этот патч поддерживает PostgreSQL с таблицей `kv_store(key, value_json, updated_at)` (схема SQLite-версии проекта) и вспомогательными таблицами. Если таблицы в существующей базе устроены иначе, приложение не будет автоматически преобразовывать их и потребуется проверка схемы. Пустую PostgreSQL намеренно не инициализирует: задача — найти уже сохранённое расписание, а не создать пустое.

При отсутствии `DATABASE_URL` сохранена работа с SQLite. Не удаляйте существующую базу в панели Timeweb.
